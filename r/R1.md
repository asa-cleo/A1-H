## Part 2: Task Allocation Strategy

### When to Deploy K2-Horizon-3.7B:
1. **Automated Coding & Software Refactoring:** Code patching, unit-test synthesis, and algorithmic reasoning.
2. **Structured JSON Backend Agents:** High-reliability schema extraction where markdown fences or preambles break downstream APIs.
3. **Heavy Document Ingestion (RAG Pipelines):** Document summarization and search over long contexts where +21.3% prompt processing speed reduces latency.
4. **General Autonomous Multi-Step Agents:** Higher overall benchmark score (70.7%) and superior Chain-of-Verification performance.

### When to Deploy Spark-X2.6-4B:
1. **Interactive Conversational UI & Fast Chatbots:** Snappier user experience (+11.2% faster token streaming at 43.6 TPS).
2. **Tight VRAM Edge Hardware:** Consumes 700 MB less VRAM (~3.8 GB total), fitting comfortably on lower-tier hardware.
3. **Strict Abstention Systems:** 100% elimination of hallucinations under dedicated abstention prompts.
4. **Creative Writing & Roleplay:** Higher fluidity for storytelling, conceptual metaphor blending, and resilience against roleplay-based jailbreaks.

## Part 3: Deep Post-Training Methodologies & Catastrophic Forgetting

### 3.1 The Dual Failure Modes of LLM Post-Training
* **Catastrophic Forgetting:** When fine-tuning on a specialized domain, gradient updates overwrite pre-existing weights, eroding the model's general knowledge (math, logic, multi-turn reasoning).
* **Plasticity Loss:** Sequential training renders weight representations rigid, orthogonalizing feature spaces and drastically reducing the model's ability to learn subsequent tasks.

### 3.2 Post-Training Methodologies Taxonomy

```
Post-Training Landscape
├── 1. Parameter-Efficient Fine-Tuning (PEFT)
│   ├── QLoRA (4-bit NF4 quantized base + 16-bit LoRA adapters)
│   ├── DoRA (Weight-Decomposed LoRA: separates magnitude from direction)
│   ├── LoRA+ (Decoupled learning rates for A & B adapter matrices)
│   └── rsLoRA (Rank-Stabilized LoRA scaling by 1/sqrt(r))
├── 2. Regularized Training (Anti-Forgetting)
│   ├── NeFTune (Noisy Embedding Fine-Tuning: adds uniform noise to embeddings)
│   ├── Replay Anchoring (Mixing 5-10% general pretraining data into fine-tuning)
│   └── KL Regularization Penalty (Penalizes drift from base model logits)
├── 3. Preference Alignment
│   ├── DPO (Direct Preference Optimization: requires paired chosen/rejected)
│   ├── ORPO (Odds Ratio Preference Optimization: monolithic SFT+DPO, reference-free)
│   ├── SimPO (Simple Preference Optimization: length-normalized, reference-free)
│   └── KTO (Kahneman-Tversky Optimization: works with unpaired binary up/down data)
├── 4. Reinforcement Learning & Reasoning Distillation
│   ├── GRPO (Group Relative Policy Optimization: DeepSeek-R1 style, no critic model)
│   └── ReST / Rejection Sampling Fine-Tuning (Generate N candidates, filter, SFT)
└── 5. Model Merging & Weight Averaging
    ├── TIES-Merging (Trimming noisy deltas, electing signs, resolving interference)
    ├── DARE (Drop And REscale: randomly drops 80-90% of weight deltas)
    └── Model Soups (Greedy or uniform averaging of checkpoint weights)
```

### 3.3 Proven Anti-Forgetting Techniques

1. **NeFTune (Noisy Embedding Fine-Tuning):**
   * Adds noise $\epsilon \sim \text{Uniform}(-\alpha, \alpha)$ to token embeddings during forward pass.
   * Prevents the model from memorizing exact token patterns, forcing smoother semantic representations and boosting out-of-distribution reasoning.
2. **DoRA (Weight-Decomposed Low-Rank Adaptation):**
   * Decouples weight vector into directional norm and magnitude scalar.
   * Matches the learning dynamics of full fine-tuning without destabilizing the base model's manifold geometry.
3. **DARE-TIES Merging:**
   * After training a specialized LoRA adapter, merge it back into the base model using MergeKit with DARE (`sparsity=0.85`) and TIES sign election.
   * Drops 85% of redundant parameter shifts, eliminating catastrophic forgetting while retaining 98%+ of new task performance.
4. **LoRA+ (Learning Rate Decoupling):**
   * Standard LoRA uses the same learning rate $\eta$ for matrix $A$ (down-projection) and $B$ (up-projection).
   * LoRA+ sets $\eta_B = 16 \times \eta_A$, allowing feature transformation without distorting input embeddings.

## Part 5: Wall-Clock Training Time Estimates on Google Colab T4 (16 GB VRAM)

### 5.1 Training Environment Setup on T4
* **Precision:** 4-bit NormalFloat (NF4) via bitsandbytes + FP16 compute dtype (Turing architecture does not support native BF16).
* **Optimizer:** 8-bit Paged AdamW (`paged_adamw_8bit`).
* **Sequence Length:** 1,024 to 2,048 tokens with gradient checkpointing enabled.
* **Throughput on T4 (Unsloth QLoRA):** ~1,400 to 2,000 tokens/sec.
